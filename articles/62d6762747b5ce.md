# 【Vite + Firebase】環境変数（.env）を活用した設定値の安全な管理方法と `VITE_` プレフィックスの仕組み

こんにちは！フロントエンドのビルドツールとして絶大な人気を誇る **Vite** を使ってアプリを開発する際、Firebaseなどの外部サービスのAPIキーや設定値をどのように管理していますか？

ソースコードに直接APIキーを直書きしてしまうと、GitHubなどの公開リポジトリに誤ってプッシュしてしまった際に大変なセキュリティリスクになります。

今回は、Viteの仕組みである**環境変数（`.env`）を使った安全な設定値の管理方法**と、クライアントサイドで変数を読み込むために必須となる **`VITE_` プレフィックスの仕組み**を解説します。

---

## 1. Viteにおける環境変数の基本ルール

Viteでは、プロジェクトの最上層（`package.json` と同じ階層）に `.env` という名前のファイルを作成することで、環境変数を安全に一元管理できます。

ここで非常に重要なVite独自のルールがあります。それは、「クライアントサイド（ブラウザ側）のコードに露出させてもよい環境変数には、必ず `VITE_` というプレフィックス（接頭辞）を付けなければならない」という仕様です。

* **`VITE_` が付く変数:** ブラウザ上のJavaScript（クライアントコード）から `import.meta.env.VITE_xxx` でアクセス可能になります。


* **`VITE_` が付かない変数:** クライアント側には一切露出せず、サーバーサイドでのみ安全に保持されます（ビルド時に除外されます）。

---

## 2. 実際の `.env` ファイルの書き方

プロジェクトのルート直下に `.env` ファイルを新規作成し、Firebaseのコンソールから取得した設定値を以下のように記述します。

```env
# Viteの環境変数は必ず「VITE_」から始める必要があります
VITE_FIREBASE_API_KEY=AIzaSy... (あなたのAPIキー)
VITE_FIREBASE_AUTH_DOMAIN=your-app.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your-app
VITE_FIREBASE_STORAGE_BUCKET=your-app.firebasestorage.app
VITE_FIREBASE_MESSAGING_SENDER_ID=123456789
VITE_FIREBASE_APP_ID=1:123456789:web:abcdef

# その他の独自フラグなども定義可能
VITE_USE_PAID_STORAGE=false

```

### ⚠️ セキュリティ上の重要注意点

`.env` ファイルに記述した値は、Viteのビルド時にクライアント側のコードへ埋め込まれます。そのため、GitHubなどのリモートリポジトリに `.env` をそのままアップロードしてしまわないよう、**必ず `.gitignore` ファイルに `.env` が含まれていることを確認**してください！

---

## 3. `src/firebase.js` で環境変数を呼び出して初期化する

`.env` に定義した変数は、コード内で `import.meta.env.VITE_xxx` という形式で呼び出すことができます。

実際の Firebase 初期化モジュール（`src/firebase.js`）の実装例を見てみましょう。

```javascript
import { initializeApp } from "firebase/app";
import { getAuth } from "firebase/auth";
import { getFirestore } from "firebase/firestore";
import { getStorage } from "firebase/storage";

// Vite の環境変数から Firebase の設定値を安全に読み込み
const firebaseConfig = {
  apiKey: import.meta.env.VITE_FIREBASE_API_KEY,
  authDomain: import.meta.env.VITE_FIREBASE_AUTH_DOMAIN,
  projectId: import.meta.env.VITE_FIREBASE_PROJECT_ID,
  storageBucket: import.meta.env.VITE_FIREBASE_STORAGE_BUCKET,
  messagingSenderId: import.meta.env.VITE_FIREBASE_MESSAGING_SENDER_ID,
  appId: import.meta.env.VITE_FIREBASE_APP_ID,
};

// Firebase アプリの初期化
const app = initializeApp(firebaseConfig);

// 各サービスのインスタンスをエクスポート
export const auth = getAuth(app);
export const db = getFirestore(app);
export const storage = getStorage(app);

```

## 4. よくあるハマりどころ：「未定義（undefined）」になる原因

`.env` を設定したのに動かない場合、以下の2点を確認してみてください。

1. **変数名が `VITE_` で始まっていない:**
先述の通り、プレフィックスがない変数はクライアントコードからは読み込めません。


2. **`.env` を変更した後にサーバーを再起動していない:**
Viteの開発サーバー（`npm run dev`）の起動中に `.env` ファイルを新規作成・編集した場合、**一度サーバーを停止（`Ctrl + C`）し、再度 `npm run dev` で再起動**しないと変更が反映されません。

## まとめ

今回は、Vite環境における `.env` の活用法と、Firebase設定値を安全に分離・管理する基本を解説しました。

`.env` で環境を切り分ける仕組みを作っておくことで、ローカル開発環境と本番環境の切り替えも非常にスムーズになります。個人開発やチーム開発でFirebaseを使う際は、必ずこの環境変数による管理を取り入れましょう！
